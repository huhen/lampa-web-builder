# lampa-web-builder — правила проекта

Сборщик веб-фронта Lampa (Docker-образ + минимальный API сборки).
Документация — `docs/`.

## Правила рабочего процесса

- **Завершение реализации** (задачи, итерации, ветки) → **Push + Pull Request** в `main`. Локальный merge не используем.
- **Замеченные недочёты и бэклог** → оформляем как **GitHub issues** (не держим в переписке): краткое описание, где в коде, почему это проблема/что нужно сделать.
- **Никаких приписок об авторстве ассистента**: в сообщениях коммитов, PR и issues не добавлять `Co-authored-by`, `Generated with`, ссылки на Claude Code/ассистента/сессии. Правило действует и для субагентов.
- Язык: документация и issues — русский, технические термины на английском; код и комментарии — только английский.

## Ключевые решения дизайна (см. spec)

- Всегда собирается последний доступный upstream-коммит; параметра «коммит» в API нет.
- Кэш сборок по (домен, коммит); запись свежей успешной тестовой сборки закреплена.
- Во время тестовой сборки заказы не принимаются; очереди после рестарта сгорают.
- Две рабочие копии репозитория upstream; тестовые сборки — не на `current`-копии.
- Плейсхолдеры `{{…}}` в патчах подставляет Go-код; неизвестный токен — ошибка сборки.
- `bad_commit` — последний коммит, не прошедший тестовую сборку.
- Авторитет пина зависимостей — кэш resolved lockfile в `DATA_DIR/deps` по ключу
  (upstream-манифест, seed); `package-lock.json` в репозитории — только seed.
